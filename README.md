# Telemetry Processing Engine

A multi-stage telemetry pipeline that validates sensor readings in C, orchestrates CSV processing with Python, and generates SQL statements for database analysis.

## Overview

Telemetry data can contain hardware error values and sensor readings outside expected operating limits. This project demonstrates a simple data-processing workflow that filters sample telemetry records, exports valid measurements to CSV, and prepares SQL statements for relational database analysis.

The project combines C, Python, and SQL to demonstrate data validation, file handling, process orchestration, and analytical database queries.

## Architecture

```text
Predefined Telemetry Records
            |
            v
        parser.c
   - Validate readings
   - Filter invalid records
   - Export valid data
            |
            v
   clean_telemetry.csv
            |
            v
        ingest.py
   - Compile C program if needed
   - Run the C engine
   - Read the CSV file
   - Generate SQL INSERT statements
            |
            v
       database.sql
   - Define the database table
   - Rank sensor readings
   - Calculate cumulative sums
```

The current implementation processes six predefined telemetry records. Python generates SQL statements and prints them to the terminal; it does not yet connect to MySQL or execute the statements automatically.

## Quick Start

### Requirements

- Git
- Python 3
- GCC compiler
- MySQL 8.0+ (optional for running the SQL queries)

### Clone and Run

```bash
git clone https://github.com/vedantguptatech-ops/telemetry-processing-engine.git
cd telemetry-processing-engine
python3 ingest.py
```

The Python script checks whether the compiled C executable exists. If it does not, the script attempts to compile `parser.c` before running the pipeline.

If compilation fails because the math library is not linked, the executable can be compiled manually:

```bash
gcc parser.c -o parser -lm
```

Then run the pipeline again:

```bash
python3 ingest.py
```

**Note:** The current script recompiles the C source only when the executable is missing. If you modify `parser.c` while an older executable still exists, remove the executable with `rm parser` and run `python3 ingest.py` again to compile the updated source.

## Data Validation Rules

The C program applies the following validation rules:

- **Hardware sentinel filtering:** Rejects readings sufficiently close to `-9999.0`, using a floating-point tolerance of `0.001`.
- **Temperature range filtering:** Rejects readings below `-40.0` or above `85.0`.
- **CSV formatting:** Exports latitude and longitude to six decimal places and sensor readings to two decimal places.

These thresholds are demonstration assumptions. A real system should use limits appropriate to the specific sensor and its technical specifications.

## Expected Output

The predefined input contains six packets:

| Packet ID | Sensor reading | Result |
|---|---:|---|
| 101 | 24.5 | Accepted |
| 102 | -9999.0 | Rejected: sentinel value |
| 103 | 26.1 | Accepted |
| 104 | 115.0 | Rejected: outside temperature range |
| 105 | 23.8 | Accepted |
| 106 | -9999.0 | Rejected: sentinel value |

The generated `clean_telemetry.csv` should contain three valid records:

```csv
packet_id,latitude,longitude,sensor_reading
101,12.970000,77.590000,24.50
103,12.990000,77.610000,26.10
105,13.010000,77.630000,23.80
```

The Python script reads these records and prints a corresponding SQL `INSERT` statement for each one.

## Database Analysis

The `database.sql` file defines a `satellite_telemetry` table containing packet identifiers, geographic coordinates, sensor readings, and a timestamp that defaults to the insertion time.

It also includes two analytical queries.

### 1. Ranking Sensor Readings

The first query uses window functions:

- `ROW_NUMBER()` assigns a sequential row number to each record.
- `RANK()` assigns rankings based on sensor readings, with equal readings receiving the same rank.

### 2. Cumulative Sensor Readings

The second query uses:

```sql
SUM(sensor_reading) OVER (ORDER BY recorded_at)
```

This calculates a running sum of sensor readings ordered by timestamp. It is an analytical demonstration, not a physical thermal-load model.

**Important:** The SQL schema and queries must be run against a MySQL database containing records before they can produce meaningful results. The Python script does not currently populate the database automatically.

## Current Limitations

- The C program processes a predefined array rather than live hardware data or an external telemetry file.
- The Python script generates SQL statements but does not execute database inserts.
- An existing compiled executable can become outdated when the C source changes.
- The cumulative sum does not account for elapsed time, sampling intervals, or a physical model of thermal energy.
- Automated tests have not yet been added.

## Future Improvements

- Support telemetry input from external files or sensor interfaces.
- Recompile the C program automatically when its source changes.
